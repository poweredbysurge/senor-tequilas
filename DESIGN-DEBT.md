# Design debt

Things this port fixes in code that would be better fixed upstream in Claude Design.

`design/pages/` is never edited. It is the Gate-A-verified record of what the design is.
Every deliberate deviation lives in a small explicit overlay beside it:

| overlay piece | what it carries | status |
|---|---|---|
| `design/LINK-MAP.json` | every link whose destination changes | built, awaiting review |
| a `max-width: 767px` CSS block | the mobile nav rule | not written yet |
| a mobile menu component | the panel and its toggle | not written yet |

**Every entry below comes back on the next export unless it is fixed upstream.** More
exports are coming: the Taco Tuesday deal, the happy hour specials, the Pa' los Niños items
and the remaining WordPress image sweep all still run through Claude Design.

---

## 1. The header nav points at nothing, on all twenty pages

**The single most important thing for the next Claude Design pass to know.**

On 19 of 20 pages every header nav link is a bare `#`. On the homepage they are in-page
anchors that work only on the homepage. The logo is `#` everywhere. Across all 20 pages
there are 721 links and **zero** real internal paths.

This is not a defect in the design work. Claude Design produces artboards, and artboards do
not navigate. A nav label on a canvas is type on a header, not a destination, and a bare `#`
is what a design tool emits when a link has no meaning yet. Finding no internal paths in an
artboard export is the expected result.

It matters anyway, because this site's SEO architecture rests on internal linking: dish pages
feeding `/menu` and `/takeout-delivery`, the events cluster cross-linking between hub,
quinceañeras, weddings and catering, the local page pointing back at the money pages. Twenty
pages with no internal links is twenty orphans.

**Port fix:** `design/LINK-MAP.json`, 389 links rewritten, generated by
`node scripts/link-map.mjs`. Destinations for the cross-page anchors come from the internal
linking rules in `design/brief/seo-migration-kit-and-page-spec.md`, not from guesswork.

**Upstream fix:** give nav items real destinations in the design, or accept that navigation
lives in code and expect this map to be re-applied after every export.

## 2. "Tonight" has no page

The nav item labelled "Tonight" appears on all 20 pages, 40 links counting the footer, and
there is no `/tonight` page among the twenty. It is mapped to `/taco-tuesday`, which owns the
seven-night calendar. The eyebrow on the homepage panel says "Thursday" while the destination
is the weekly specials page, so the label and the destination do not quite agree.

**Open with the client.** Either rename the item, or add the page.

## 3. Third-party delivery links have no destinations

`/takeout-delivery` has DoorDash, Uber Eats and Grubhub controls, all `#`. No storefront URL
for any of them appears in the design or anywhere in the brief. Left `unresolved` in the map
rather than guessed.

## 4. Google and Yelp were not in the design

Both footer controls were `#`. Resolved outside the design:

- Yelp: `https://www.yelp.com/biz/senor-tequilas-germantown-2`
- Google listing: `https://www.google.com/maps/place/?q=place_id:ChIJfQWUP2wstokR0hf-aq2yO5Y`
- Google write-a-review, the separate homepage control beside the review count:
  `https://search.google.com/local/writereview?placeid=ChIJfQWUP2wstokR0hf-aq2yO5Y`

Note for anyone editing these later: `facebook.com/senortequilasgermantown` turns up in
search and is the **old, inactive** page. The design's `facebook.com/senortequilasDMV` is
current and correct. Do not "fix" it.

## 5. Mobile navigation depends on a runtime that cannot be exported

*Recorded now; the port fix is not built yet.*

The hamburger opens a real menu on the **homepage only**. It is a fixed overlay at z-index
100 with eight links and a close button, built on click by the design's React runtime. The
other **19 pages have a decorative hamburger that does nothing at all** (element count
identical before and after a click). None of it survives a static export, because the panel
does not exist in the DOM until the runtime creates it.

Separately, the desktop `<nav>` is never hidden: it computes to `display: flex` at every
width from 360 to 1920, so every page scrolls sideways from 360 up to between 653 and 724
depending on how many links that page's nav carries.

**Port fix, once approved:** lift the design's own panel markup, drive it with about fifteen
lines of vanilla JavaScript (toggle `aria-expanded`, Escape to close, close on link
activation, move focus in and back), and hide the desktop nav under `max-width: 767px`.

The eight panel links and their destinations, recorded so a future export cannot silently
revert them:

| panel item | design href | destination |
|---|---|---|
| Eat / Menu | `#menu` | `/menu` |
| Thursday / Tonight | `#tonight` | `/taco-tuesday` (see entry 2) |
| Mon to Fri / Happy Hour | `#happy` | `/happy-hour` |
| 12 to 400 / Private Events | `#events` | `/private-parties` |
| Since 2015 / Our Story | `#story` | `/our-story` |
| Regalo / Gift Cards | `#gift` | `/#gift` |
| Order Online | Toast | unchanged |
| Reserve a Table | Toast | unchanged |

`/#gift` stays an anchor because no gift card page exists among the twenty. Root-relative
means it works from any page instead of only from the homepage.

**Upstream fix:** express the mobile header statically, or accept that navigation lives in
code.

## 6. The brief references a `/contact/` page that does not exist

`seo-migration-kit-and-page-spec.md` says "every page: link to `/contact/`". There is no
contact page among the twenty and none was designed. Not actioned. Flagging it because the
internal linking rules assume it.
